# PIM-P에 사용할 Codex 모델

검토일: 2026-10-02. 공식 OpenAI 문서와 현재 PIM-P 작업 구조를 대조한 추천이다.
동일 논문·동일 조건으로 모델별 결과를 평가한 벤치마크는 아직 수행하지 않았다.

## 추천

| 상황 | 시작 조합 | 조정 |
|---|---|---|
| normal 전체 제작 | GPT-6.1 Sol + High | 복잡한 수식·방법이나 결과의 모순이 있으면 Astra + High 검토 |
| easy 전체 제작 | GPT-6.1 Sol + High | 직관·비유의 정확성과 교육용 구성이 특히 중요하면 Astra + High 검토 |
| 품질을 최우선으로 하는 발표 | GPT-6 Astra + High | 까다로운 분석·검증이 남아 있으면 Extra High 검토 |
| 이미 검증된 자료의 제한된 수정 | GPT-6.1 Sol + Medium 또는 GPT-6 Luna + High | 내용이 바뀌면 원문과 다시 대조 |

High는 이 프로젝트의 시작 설정 제안이다. 공식 문서의 모델 기본값과 같은 뜻은 아니다.
사용 가능한 모델·추론 수준은 계정, 워크스페이스 정책, 클라이언트와 배포 상태에 따라 달라진다.
Max/Ultra를 일괄 권장하지 않는다. 추론 수준을 올리면 시간·토큰 사용이 증가할 수 있으며,
API 토큰 단가를 Codex 구독의 사용 한도나 실제 발표 한 편의 비용으로 환산하지 않았다.

## normal과 easy를 같은 모델로 시작하는 이유

normal은 PDF 페이지 이미지와 텍스트를 대조해 표·수식·실험 조건을 읽고,
저자 주장과 리뷰어 해석을 구분한 brief를 작성한다. 그 뒤 발표 구성·JSON·PPTX·검사를 수행한다.
필요한 능력은 논문 해석, 시각 자료 이해, 긴 문서의 일관성 유지, 도구 실행과 오류 복구다.

[easy 정책](../skills/pimp/references/easy-mode.md)은 기술 분석 §0–§12를 모두 작성한 후
§13의 쉬운 설명을 추가하도록 한다. 비전공자용 표현에서도 방법의 논리, 지표 방향,
연구 한계와 비유의 한계를 보존해야 한다. 따라서 easy라는 이름만으로 더 작은 모델이나
더 낮은 추론 수준을 선택할 근거는 없다. 이 판단은 스킬의 요구 사항에서 도출한 해석이다.

PPTX 생성은 같은 Python·Node 도구와 레이아웃을 사용한다. 모델을 바꾸면 내용 선택·설명·계획·검증에
차이가 생길 수 있으나, 폰트·렌더러의 문제를 해결하거나 사실 정확도를 자동으로 보증하지 않는다.

## 공식 정보와 프로젝트 판단

[공식 Codex 모델 안내](https://learn.chatgpt.com/docs/models?surface=app)는 GPT-6.1 Sol을
복잡한 에이전트 작업의 추천 모델로 설명하고, Astra를 어려운 연구·도구 작업,
Luna를 범위가 명확하고 반복적인 작업에 대응시킨다. High/Extra High는 다단계 분석에 적합한 선택지로 설명한다.
[공식 모델 선택 안내](https://developers.openai.com/api/docs/guides/model-selection)는
동일 작업에서 모델과 추론 설정을 비교해 요구 품질을 만족하는 조합을 선택하도록 권한다.
[GPT-6.1 Sol 모델 문서](https://developers.openai.com/api/docs/models/gpt-6.1-sol)는
복잡한 작업에서 Astra에 가까운 성능과 비용의 균형을 설명한다.

이를 PIM-P의 분석→설명→슬라이드→검증 흐름에 적용해 Sol + High를 기본 시작점,
Astra + High를 더 까다로운 논문과 품질 우선 발표의 후보로 선택했다.
이는 PIM-P에서 측정한 우열·정확도·시간·비용의 결과가 아니다.
이 저장소의 자동 테스트는 실행 코드의 동작을 검증하며 모델의 논문 이해 성능을 비교하지 않는다.

## 실제 사용

모델 선택 메뉴에서 모델과 추론 수준을 고른 뒤 PDF를 첨부하고 `$pimp normal` 또는 `$pimp easy`를 요청한다.
스킬 명령은 모드를 선택하며 모델 선택 메뉴를 바꾸지 않는다.
normal/easy 결과는 각각 다른 작업 폴더로 만들어 PPTX·노트·QA 결과를 구분한다.
둘 다 필요하다면 검증된 기술 brief §0–§12를 공통 근거로 사용하고 easy에는 §13을 추가하도록 요청할 수 있다.
모델을 바꾸거나 brief를 재사용해도 원문 수치·방법·한계와 각 결과의 렌더를 확인한다.

향후 비교 실험은 같은 PDF, 발표 시간, 장수, 언어와 도구 환경에서 진행한다.
표·수식 오류, 근거 누락, 저자/리뷰어 관점 혼동, easy 비유의 오류,
방법·한계의 누락, PPTX 표시 문제와 실제 소요 시간·사용량을 함께 평가해야 한다.
